# s3nbd

[English](README.md) | Русский | [简体中文](README_CN.md) | [Español](README_ES.md) | [Français](README_FR.md)

NBD-сервер на Go, который хранит блочные устройства в S3-совместимом хранилище. Поддерживает несколько именованных устройств, по одному активному клиенту на каждое. NBD работает по TCP или Unix-сокету без TLS; для S3 используются HTTP или HTTPS, адресация path-style и Signature V4.

## Быстрый старт

Понадобятся Go 1.26+, заранее созданный бакет S3 и `nbd-client` на Linux.

```sh
go build -o s3nbd .
cp config.example.json config.json
```

Укажите в `config.json` адрес S3, регион, бакет и размеры устройств, затем запустите сервер:

```sh
export S3_ACCESS_KEY=your-access-key
export S3_SECRET_KEY=your-secret-key
./s3nbd -config config.json
```

В другом терминале подключите устройства:

```sh
sudo modprobe nbd
sudo nbd-client 127.0.0.1 10809 /dev/nbd0 -N disk1
sudo nbd-client 127.0.0.1 10809 /dev/nbd1 -N disk2
```

Теперь их можно отформатировать и смонтировать стандартными средствами Linux. Перед остановкой сервера размонтируйте файловые системы и отключите NBD.

## Unix-сокет

Для локального доступа задайте `"Listen": "unix:/run/s3nbd/nbd.sock"`. Создайте родительский каталог с правами `0700` от имени пользователя, запускающего s3nbd. Сокет получает права `0600`; клиент должен работать от того же пользователя или root. Существующие файлы и сокеты не перезаписываются. При штатной остановке сокет удаляется; после аварии удаляйте оставшийся сокет вручную, только убедившись, что сервер его не использует.

```sh
sudo install -d -m 0700 /run/s3nbd  # server running as root
sudo nbd-client -unix /run/s3nbd/nbd.sock /dev/nbd0 -N disk1
```

## Настройки

Полный пример — в [config.example.json](config.example.json).

| Параметр | Назначение |
| --- | --- |
| `LogLevel` | Минимальный уровень логов: `debug`, `info` (по умолчанию), `warn`, `error`; регистр не важен. Применяется при запуске; неизвестное значение запрещает запуск. Логи выводятся в stderr с временем и уровнем. Статистика и запуск/остановка — info, подключения и команды NBD — debug, предупреждения — warn, ошибки операций — error. |
| `Listen` | Адрес прослушивания NBD (`host:port` / `unix:/absolute/path`); `0.0.0.0:10809` — все IPv4-интерфейсы. По умолчанию `127.0.0.1:10809`. |
| `Endpoint`, `Region` | Адрес S3 и регион для подписи запросов. |
| `Devices` | Параметры каждого устройства: `Name`, `Bucket`, `Prefix` и `Size` в байтах. |
| `BlockSize` | Размер одного объекта S3 в байтах. Размеры устройств должны быть кратны ему. |
| `CacheBlocks` | Число блоков в кэше каждого устройства. |
| `Workers` | Параллелизм запросов S3 и максимальное число активных чтений NBD на устройство. |
| `FlushSeconds` | Интервал фонового сброса данных в хранилище. |
| `YandexPatch` | Включает PATCH в Yandex Object Storage; по умолчанию выключен. |
| `InsecureTLS` | Отключает проверку сертификата S3; по умолчанию выключен. |

Для временных учётных данных задайте `S3_SESSION_TOKEN`. Для собственного центра сертификации используйте системное хранилище доверенных сертификатов или `SSL_CERT_FILE`.

## Хранение и сохранность данных

**Запись подтверждается после попадания в RAM. При аварии все несброшенные данные теряются.** FLUSH и запись с FUA ждут сохранения накопленных изменений в S3. При ошибке загрузки блоки остаются изменёнными для повторной попытки, а клиент получает `EIO`.

Фоновый сброс выполняется каждые `FlushSeconds`, а также при отключении клиента и получении SIGINT/SIGTERM. Если последний сброс завершается неудачно, сервер выходит с ошибкой; оставшиеся в RAM данные не сохраняются.

Каждый объект `Prefix/blocks/<16 hex digits>` хранит один блок; имя заканчивается 16 шестнадцатеричными цифрами. Отсутствующие объекты читаются как нули. Записи накапливаются в кэше без GET-запросов. При сбросе частично изменённого блока сначала загружаются существующие данные, затем блок отправляется целиком. Полная перезапись не требует чтения. Полностью нулевые блоки удаляются вместо загрузки.

Кэш занимает до `CacheBlocks × BlockSize` байт **на устройство**, не считая памяти для запросов и SDK. Активные чтения могут дополнительно занимать до `Workers × 32 MiB` под буферы ответов. Когда кэш заполнен, сервер вытесняет неизменённый блок или сбрасывает изменённые. Чтения выполняются параллельно; запись, освобождение блоков и сброс ждут завершения предшествующих чтений.

Ограничения:

- Не меняйте размеры устройств и `BlockSize` для существующих данных: эти значения хранятся только в конфигурации.
- Для каждой пары бакет/префикс используйте один сервер и не изменяйте его объекты извне.
- Хранилище должно обеспечивать согласованность чтения после записи и долговечность подтверждённых записей. Сброс нескольких объектов не является атомарной операцией.
- NBD использует согласование fixed-newstyle с именованными экспортами, READ/WRITE, FLUSH, FUA и TRIM. Размер запроса READ/WRITE ограничен 32 MiB; поддержка нескольких соединений не объявляется.

## Освобождение блоков

Чтобы освободить неиспользуемые блоки файловой системы, выполните `sudo fstrim /mountpoint`. Полностью освобождённые блоки удаляются из S3 пакетами; при частичном освобождении обнуляется выбранный диапазон. Обе операции буферизуются до сброса, но чтение сразу возвращает нули. При ошибке удаления блок остаётся изменённым для повторной попытки.

Если в S3 включено версионирование, удаление создаёт маркер удаления. Для очистки старых версий настройте политику жизненного цикла хранилища.

## PATCH в Yandex Object Storage

Задайте `"YandexPatch": true`, `"Region": "ru-central1"` и соответствующий HTTPS-адрес. **Версионирование бакета должно быть выключено.** PATCH — расширение Яндекса, не входящее в стандарт S3.

При частичном обновлении существующих объектов этот режим отправляет только изменённые диапазоны, без скачивания и загрузки блока целиком. Для новых объектов и полной перезаписи используется PUT, для полного освобождения — пакетное удаление. Если PATCH возвращает `404 NoSuchKey`, сервер выполняет PUT целого блока с нулями вне изменённых диапазонов. При других ошибках блок остаётся изменённым для повторной попытки, а FLUSH/FUA завершается ошибкой.

Подробнее — в [документации PATCH API](https://yandex.cloud/ru/docs/storage/s3/api-ref/object/patch).

## Логи и тесты

Каждые пять секунд сервер пишет в лог:

- `S3 stats`: число запросов и байты тел запросов/ответов по HTTP-методам, суммарно по всем устройствам. Учитываются повторы и ошибки, но не заголовки и накладные расходы TCP/TLS.
- `cache stats`: число изменённых объектов и их размер в байтах на устройство. Размер считается по целым блокам, включая ожидающие удаления, а не только по изменённым диапазонам.

Запуск тестов:

```sh
go test -race ./...
```
